- Read the Makefile, and use make targets directly for any action that is relevant, especially build/test/run needs.
- Always check your work by running `make test`. If you're writing new business logic, add new tests that cover a reasonable range of cases. When tests fail, check the logic, not the test. If the logic looks correct, don't change the test, but surface the problem and likely solution to me. In other words, you are expected to write correct tests to the best of your ability, but should not edit tests unless explicitly asked to.
- This project is unreleased, and undeployed. Backwards compatibility is **not** something we should aim for: when making a breaking change, always bias towards  a "clean break" that makes the system more correct. Never create versioned migrations, or leave doors open for "existing installations", because there aren't any. Trying to maintain backwards compatibility at this stage is more of a risk than a benefit, because it can make code messy and vulnerable.
